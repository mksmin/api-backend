# Мини-LMS — бизнес-требования MVP

## Цель и границы

Мини-LMS заменяет Excel как рабочий журнал образовательного проекта. Организатор создаёт проект, администратор ведёт списки и расписание, кураторы отмечают посещаемость, а администратор и владелец выгружают журнал и сводку в Excel.

Например, «Атом-лаб 2026, осень» — образовательный проект, «Поток 3 · Кибербез» — один из его потоков. В проекте может быть несколько потоков, у каждого участника один текущий поток в проекте. Участники в MVP — записи в списках. Самостоятельная регистрация и личный кабинет со своими проектами и потоками предусмотрены на следующем этапе.

## Роли и доступ

| Действие | Куратор | Администратор | Владелец |
| --- | --- | --- | --- |
| Смотреть расписание | В своём проекте | В своём проекте | В своём проекте |
| Смотреть списки и вести посещаемость | В назначенных потоках | Во всех потоках проекта | Во всех потоках проекта |
| Зачислять, переводить и исключать участников | — | Да | Да |
| Создавать потоки, вести расписание, выгружать Excel | — | Да | Да |
| Редактировать основные сведения о проекте | — | — | Да |
| Назначать и отзывать роли, приглашать сотрудников | — | — | Да |

- **Создание проектов.** Право создания выдаётся организатору отдельно. Создатель становится владельцем нового проекта.
- **Назначения.** Роли действуют в пределах проекта. Куратору можно назначить один или несколько потоков. Владелец может назначить существующий аккаунт или пригласить нового сотрудника по email. Одноразовое приглашение привязано к адресу, проекту и роли. Назначение вступает в силу после подтверждения адреса по ссылке из письма. Отзыв роли закрывает доступ к проекту при следующем обращении.
- **Проверка доступа.** Кабинет и API доступны сотрудникам с соответствующим правом. При работе с участником или занятием сервер проверяет их принадлежность проекту, а для куратора также проверяет назначение на текущий поток участника. Изменяющие запросы с cookie требуют защиты от CSRF.

## Списки, расписание и посещаемость

- **Списки.** Администратор и владелец могут добавить участника вручную или импортировать XLSX по единому шаблону с ФИО, email и потоком. Email уникален в пределах проекта и используется для учёта. Повторный импорт пропускает существующие адреса и показывает ошибки по строкам. Перевод и исключение выполняются отдельными действиями. При переходе из Excel переносятся списки участников и их потоки. Занятия и отметки ведутся в LMS с даты перехода.
- **Расписание.** Занятие имеет название, дату, время начала и окончания. Расписание общее для всех потоков проекта. Часовой пояс проекта по умолчанию — `Europe/Moscow`.
- **Журнал.** Для участника на занятии доступны состояния «Был», «Отсутствовал» и «Не отмечен». Куратор может исправить отметку после занятия в пределах назначенных потоков. Изменение отметки и запись в истории сохраняются вместе. История показывает автора, время, прежнее и новое значение, а также изменения состава проекта, включая переводы и исключения.
- **Текущий состав.** Рабочий журнал строится по текущему списку участников. После перевода прежние отметки участника отображаются в новом потоке. Позднее зачисленный участник появляется в прошедших занятиях как «Не отмечен». После исключения участник исчезает из рабочего журнала, а его отметки доступны в истории.
- **Отмена занятия.** Занятие и отметки сохраняются. Для куратора и администратора журнал отменённого занятия доступен только для чтения. Владелец может исправлять отметки с записью в историю.

## Выгрузка Excel

Администратор или владелец выбирает проект и период и получает один файл XLSX с двумя листами.

- **«Журнал»** — участник, текущий поток, занятие, дата и статус посещения. Отменённые занятия помечаются отдельно. Сохранённые отметки видны.
- **«Сводка»** — число присутствий, отсутствий и незаполненных отметок по каждому потоку и процент посещаемости. Процент равен числу присутствий, делённому на число всех ожидаемых отметок за завершённые занятия периода. Незаполненные отметки входят в знаменатель. Отменённые занятия исключаются из расчёта. При нулевом знаменателе показывается «—».

Выгрузка формируется по запросу из текущих списков. После зачисления, перевода или исключения повторная выгрузка за тот же период может показать другие результаты. Изменение можно проследить в истории.

## Подключение и отключение

- У LMS свой кабинет `/lms`, API `/api/v2/lms` и образовательные проекты, отдельные от раздела «Твои проекты». Для входа используются существующие аккаунты сотрудников и общая аутентификация приложения.
- Модуль по умолчанию выключен. `API_CONFIG__LMS__ENABLED=true` включает его после перезапуска всех экземпляров приложения. При выключении кабинет, API и ссылки приглашений возвращают `404`. После повторного включения прежние данные снова доступны.
- Граница реализации — `app/subprojects/lms/`, отдельные таблицы LMS в общей PostgreSQL и шаблоны `templates/lms/` во frontend-репозитории. Роутер регистрируется только при включённом модуле. Миграции входят в общую цепочку Alembic и применяются перед первым включением. Модели доступны Alembic при любом положении флага. Для приглашений при включённом модуле настраивается почтовый транспорт.

## Этапы и критерии приёмки

1. **Подключение и доступ.** Организатор создаёт образовательный проект с двумя потоками. Сотрудник без назначения не может открыть проект. После выключения прямые URL кабинета, API и приглашений возвращают `404`. После повторного включения проект и его данные доступны назначенным сотрудникам.
2. **Рабочий журнал.** Администратор дважды импортирует один список и получает один набор участников. Куратор ставит и исправляет отметку в своём потоке и получает отказ при прямом обращении к участнику другого потока. После перевода прежняя отметка отображается в новом потоке. После исключения участник исчезает из текущего журнала, а его отметка и изменения состава доступны в истории.
3. **Приглашения и выгрузка.** Новый сотрудник получает роль после подтверждения email. Повторное использование ссылки не даёт нового назначения. После отзыва доступа сотрудник теряет право на операции проекта. Для четырёх ожидаемых отметок с двумя присутствиями, одним отсутствием и одной незаполненной строкой сводка показывает **50%**. После отмены отметки сохраняются в журнале, куратор и администратор теряют возможность их менять, а занятие исключается из сводки.
